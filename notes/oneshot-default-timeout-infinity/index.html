Type=oneshot defaults to TimeoutStartSec=infinity; a hung run stops the timer

2026-08-23 · Linux services#systemd#ssh#timeouts

Symptom

A sync service run started while DNS was down sat in activating for over two minutes. While the service is active the timer schedules nothing, so memory sync stood still with no alert: the script never reached its alert branch.

Cause

For Type=oneshot the default TimeoutStartSec is infinity, and ssh without ConnectTimeout waits for the TCP timeout for minutes. The script had a 'broke' branch but no 'hung' branch, although for a periodic job hanging is worse than failing: a failure shows in the log and unit status, a hang looks like silence.

Rule

Bound a periodic job's time in two places: in the command itself (ConnectTimeout/ServerAliveInterval for ssh, --max-time for curl) and in the unit (TimeoutStartSec below the timer period times a small factor). Test not only 'what if it fails' but 'what if it never answers'.
