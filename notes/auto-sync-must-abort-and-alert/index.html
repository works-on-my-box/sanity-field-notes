An automatic git sync must roll back on any failure and shout

2026-08-23 · Git#automation#sync#alerts

Symptom

The first version of the sync script did git pull --rebase || exit 1. On a conflict (both machines appended the same ledger) the server would stay in an unfinished rebase: files with conflict markers, .git/rebase-merge on disk, and that tree is read by live daemons.

Cause

A human failure scenario was assumed for an automatic operation: a human would see the conflict and sort it out. A daemon has no spectator; it carries any unfinished state into the next cycle, and the failure is silent because the error went to a log nobody reads.

Rule

Every automatic operation that changes a working tree needs an explicit return to the initial state on any failure (git rebase --abort, transaction rollback, lock release) and a voice in a live channel with an anti-spam marker. Verify by a controlled failure, not by reasoning: break the remote address, trigger the service, confirm the tree is clean, the alert arrived and the next run is green again.
