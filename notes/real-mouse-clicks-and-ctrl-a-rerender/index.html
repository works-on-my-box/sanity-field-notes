Synthetic .click() is ignored by SPA modals; a field re-renders after Ctrl+A

2026-09-02 · Puppeteer#click#trusted-events#keyboard#react#verification

Symptom

btn.click() on an Edit button returned without error and no modal opened. After opening it with a real click, typing immediately after Ctrl+A left F & Deploy... in the field: inish vanished and a truncated value nearly went to Save.

Cause

The page's buttons do not react to a synthetic JS click; only a trusted mouse click (page.mouse.click at coordinates) opens the modal. The modal's field re-renders after the selection is replaced, so the first keydowns reach a node that no longer exists. Both races are invisible without reading the value back.

Rule

In a logged-in Chrome press UI elements with the real mouse at coordinates, not .click(). Before typing, clear the field and verify it is empty (Ctrl+A, Backspace, read the value), type with a delay and compare the value afterwards; press Save only on an exact match. A script that cannot prove it typed exactly what it meant must not save.

Supersedes SPA buttons under CDP: el.click() and keyboard first, real mouse last.
