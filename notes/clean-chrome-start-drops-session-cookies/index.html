Chrome drops session cookies on a clean start unless restore_on_startup=1

2026-09-25 · Chrome & DevTools Protocol#cookies

Symptom

A vendor dashboard login made from the server's second Chrome worked one day; the next day the same profile opened the login page again, which was recorded as 'session expired' and led to a wrong conclusion that the dashboard needed another machine.

Cause

The dashboard's only login cookie session is a session cookie (no expiry, httpOnly). On a clean start Chrome deletes session cookies unless the profile has 'Continue where you left off' (session.restore_on_startup = 1); the default is 'New tab' (5). Every visit that ended by stopping that Chrome would therefore begin with a fresh login.

Rule

In the profile that holds dashboard logins set session.restore_on_startup = 1 (via chrome.settingsPrivate.setPref on chrome://settings, not by editing the file); after any new login, restart and verify the login is still alive. Before writing 'session expired', inspect the login cookie's expiry (page.cookies(): session: true means a session cookie).
