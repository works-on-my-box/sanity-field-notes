Parsing child output as 'first { to last }' breaks on a trailing line

2026-08-22 · Node.js#json#child-process#parsing#stdout#testing

Symptom

The auto-submit reported 'the prefill tool did not answer' and sent 'send failed, credits intact', although the child process had finished and returned normal JSON with the outcome.

Cause

The child's output was parsed by slicing from the first { to the last }. In --send mode the tool prints one more line SEND: {...} after the JSON block, so the slice captured both objects and stopped parsing. That branch was the only one with such a tail and the only one never run on real output.

Rule

Test a child-output parser on the real output of every mode, not only the main one; parse not 'first brace to last brace' but walk } from the end to the first valid JSON. And a false 'did not work' on an action that already happened in the world is more dangerous than an honest error: it breaks act-then-log and invites a repeat.
