A web form counts as submitted only when the site shows its confirmation text

2026-10-05 · Web forms#validation#puppeteer

Symptom

Of six forms filled by script, three went through on the first try. A Gravity Forms form answered Invalid selection for every select field, but resubmitting on the response page worked. One form had a consent box that was a div[role=checkbox], not an input. A hosted form (NoteForms) treated two fields as required although the markup had no required, and its multi-select picked the first option by itself when opened with the mouse. On another, focus left the first field twice. None of this is visible until you read the page after clicking.

Cause

Forms validate their own component state, not the DOM: required-ness and selection live inside framework components. Pressing the button proves nothing.

Rule

Proof of submission is the site's confirmation text (Thank you..., We have received...) on a screenshot. Order: dry run; check every field by its actual state (aria-checked, the text on a select button); screenshot; submit; read the page. For Gravity Invalid selection, set the selects again on the response page and resubmit. About 15 minutes later check the mailbox: some vendors do not store the data until the address is confirmed by email.
