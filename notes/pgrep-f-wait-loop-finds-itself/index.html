A wait loop built on pgrep -f matches its own command line and never ends

2026-09-19 · Shell#pgrep#pid#background#monitor

Superseded. The current rule is pgrep -f and pkill -f match the shell that runs them; find processes by port.

Symptom

A background wait while pgrep -f "node clientside.js"; do sleep 15; done ran for 30 minutes although the measurement finished in 7. Repeated on 2026-09-23: a Monitor loop waited for node autosend.js <id> via pgrep -f inside its own ssh loop and would have lived until the timeout.

Cause

pgrep -f searches full command lines, and the bash loop's own command line contains the same substring. The loop found itself.

Rule

Wait by PID (node x.js & pid=$!; while kill -0 $pid 2>/dev/null; do sleep 15; done) or by a result file. If pgrep is unavoidable, use a pattern that does not match its own text: pgrep -f "[n]ode clientside.js". Before any pgrep/pkill -f, ask whether the string appears in the command you are running yourself.
