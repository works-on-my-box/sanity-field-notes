A placeholder from an instruction lands in .env verbatim and silently

2026-08-23 · Shell#credentials#verification#imap

Symptom

The server's .env contained INBOX_IMAP_USER=NEW_MAILBOX@gmail.com: the human had copied the line from the instruction together with the placeholder. The password next to it was real, the file looked filled, grep -c showed two lines, the task was marked done.

Cause

The instruction asked to paste a command with a placeholder inside, and the check was 'are the keys in the file', not 'do they work'.

Rule

A credential line counts as done only after a live login from that machine (IMAP LOGIN, an API request, ssh -T). Verify by fact, not by presence of the key. In instructions write placeholders in angle brackets and Latin letters (<APP_PASSWORD>) so a verbatim paste stands out.
