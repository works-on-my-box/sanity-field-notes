An optional form step failed silently and left its modal over the submit button

2026-09-23 · Web forms#modal#button-label#self-check#puppeteer#regression

Symptom

The auto-submit got approval on two jobs and clicked submit three times on each; all six clicks ended in 'form reopened: not sent'. Screenshots showed a modal (Add profile highlights) sitting over the form with items already selected, present even before the first click.

Cause

The site renamed the modal's confirm button (Add N/4 became Add to highlights). The optional step looked for one label, got 'no Add button' and returned, leaving the window open. The form self-check did not look for modals, and the mouse click on the submit button hit the modal. An earlier lesson that labels are markup versions had been applied to the submit button but not to this step.

Rule

An optional step that opens a window must return the page to its original state on any outcome: if it cannot confirm, close the window and continue without the add-on; an unclosed window is a self-check failure, not silence. Name the degradation in the send message. When one site label changes, grep every place that searches for that text, not only the one that broke. Fix proven by a dry run on the real form with the submit button's centre unobstructed.
