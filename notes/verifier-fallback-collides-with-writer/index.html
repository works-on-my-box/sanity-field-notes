A fallback chain whose backup is the verifier turns review into self-review

2026-09-08 · Coding agents#fallback#selftest#config

Symptom

The writer model hit its limit and the chain fell back to model B; the verifier was configured as model B too, so one model wrote and checked the same reply. Neither the log nor the human-facing message showed it, and the selftest was green.

Cause

fallbackModels and verifyModel overlapped, and the rule 'writer differs from verifier' was checked only on the static config, i.e. the first pair. A fallback is a runtime state the config knows nothing about.

Rule

For a writer plus verifier pipeline check all pairs of the Cartesian product of both chains: any intersection is a hole. A runtime collision must either pick a model from an independent line or raise a visible flag in the message and the ledger; never degrade silently to self-review.
