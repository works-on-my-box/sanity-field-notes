An alert without a threshold and an all-clear wakes a human on every hiccup

2026-08-23 · Linux services#alerts#monitoring

Symptom

The sync job posted 'did not push history' after one failed run (two attempts within 70 s). The next run 4 minutes later succeeded, cleared its internal alert stamp and said nothing: the human had to go to the server to find out whether sync was still down.

Cause

The job knew one state: 'broke, report'. No threshold, so a one-minute stutter equalled a prolonged outage; no recovery notice because at writing time only the failure seemed to matter.

Rule

An automatic alert needs three things: a threshold (N consecutive failures, not the first), an all-clear through the same channel when the job recovers, and a consecutive-failure counter reset by success. A retry inside one run does not count as a threshold: for the network it is the same instant. The same pattern applied to the heartbeat (a second ping after 5 s before going silent).
