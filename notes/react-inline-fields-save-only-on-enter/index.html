React inline fields save only on Enter after validate(); fill() skips state

2026-08-26 · Web forms#react#native-setter#typeahead#validation#fiber

Symptom

A profile title 'saved' (the field went readonly) but came back old after reload; fill into a textarea put 542 characters into the DOM while the counter still said Minimum 150 characters; skill suggestions never appeared on programmatic input.

Cause

(1) The inline fields send nothing on blur, Tab or element.blur(); the save request goes only on Enter and only if the component's validate(text) returns null, and the error is visible only as an isError flag in React props (the tagline allowed letters, digits, spaces and , : ' ! ?; dot, dash, &, +, / and brackets were rejected). (2) fill writes the DOM value past React state; the cure is the native value setter plus dispatchEvent(new Event('input',{bubbles:true})). (3) The typeahead reacts only to real keystrokes; suggestions render as radio labels.

Rule

For such inline fields: run the text through the component's validate from its props first (fiber then memoizedProps.validate), set the value via the native setter plus an input event, press a real Enter, then always reload and re-read the value: 'the field closed' is not 'it saved'.
