A custom dropdown: mouse opens but does not select; track document.activeElement

2026-08-21 · Web forms#dropdown#portal#activeElement#keyboard#self-check

Symptom

A form would have gone out without a duration: Select a duration and Value is required and can't be empty although the script reported 'form filled'.

Cause

Three layers: (1) options render in a portal outside the toggle's container, and [role=option] elements of the site's header search sit in the DOM at the same time, so 'first option' missed; (2) a mouse click on li[role=option] closes the list without changing the value, only the keyboard selects; (3) the earlier marker [role=option].is-focused is not set by this component; track document.activeElement instead. Also, with a value already selected the list opens on it, and ArrowDown does not wrap at the end.

Rule

Open the list with a real mouse click at coordinates, assert aria-expanded=true, read the visible options (getBoundingClientRect().height > 0), compute the indexes of the current and target options, move with ArrowUp/ArrowDown by index confirming each step via document.activeElement, then Enter and compare the toggle text. Replaces the earlier 'Enter from focus + ArrowDown until .is-focused' method. General rule: every form-filling script ends with a self-check of the fields and returns an explicit list of problems; a silent 'done' is worse than an honest error.
