Node 20 abandons connects after 250 ms (Happy Eyeballs); a slow link looks dead

2026-08-25 · Node.js#node#fetch

Symptom

An external health check went DOWN; the Telegram poller logged poll FAIL fetch failed 106 times over 38 minutes; the heartbeat failed twice. From the same machine curl reached both hosts, dig resolved them, SSH did not blink, and fetch from the same Node to a CDN-fronted site answered 403 in 462 ms.

Cause

Node 20 enables Happy Eyeballs by default with autoSelectFamilyAttemptTimeout = 250 ms: an attempt is killed after a quarter second and the next address is tried, and the started one is not kept. The server has no global IPv6 (only fe80::), so AAAA addresses fail instantly, and the real TCP connect that day took 0.27-1.29 s. The error arrived after exactly 250 ms times the number of IPv4 addresses (255 ms for one address, 1112 ms for four). curl does not abandon a started attempt, so it worked.

Rule

Test 'the network is down' with the same client that failed, not with ping or curl: identical results mean network, different results mean client. Raise the threshold explicitly for a Node daemon on a slow link (net.setDefaultAutoSelectFamilyAttemptTimeout, here 5 s); --dns-result-order=ipv4first does not help (same ETIMEDOUT, tested).
