Field notes — symptom → cause → rule, from an unattended browser-automation stack

Retry idempotent steps by default; clean up on every exit path, exit(1) too

2026-08-25 · Node.js#retries#cleanup#fallback

Symptom

A fresh item in the best band dropped out of the funnel entirely: claude FAIL error_max_structured_output_retries. No retry with the same model, no fallback to the next, and the form tab opened for a read stayed in Chrome.

Cause

Fallback was triggered only when the error text matched limit|overloaded|429|rate.?limit|credit|quota. A new kind of error ('the model could not fit the schema in N tries') missed the list and was treated as fatal. On that branch the script exited via process.exit(1), bypassing closeForm().

Rule

For an idempotent step (a request without side effects) retry by default: at least one retry on any failure, with a whitelist for errors that are pointless to retry. Every emergency exit path gets the same cleanup as the normal one: if a function opened a tab, all exits close it, including exit(1).
