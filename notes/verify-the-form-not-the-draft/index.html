Pre-send checks must read the form back, not the draft file

2026-08-21 · Web forms#forms#verification#automation

Symptom

The draft in the file was perfect while the form held something else: the amount did not land in the currency input, the duration stayed unselected, the cover letter went into the wrong textarea, a screening answer was empty. A file-based check passed all of it and allowed the send.

Cause

Between the draft and the submit button lies a prefill layer that can fail silently (custom components, portals, tab focus). The file is the intent, the form is the fact.

Rule

Any automatic pre-send check reads the form (--readback) and compares every field with the draft: amount, duration, mode, cover letter, each answer by index. A reviewing model also gets the text from the form, not the file. Take the cost from the submit button itself and compare it with the expected cost, otherwise an add-on can be sent silently.
