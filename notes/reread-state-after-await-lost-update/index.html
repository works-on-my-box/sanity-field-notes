Field notes — symptom → cause → rule, from an unattended browser-automation stack

Re-read shared state after any await; a stale copy overwrote another process

2026-09-19 · Node.js#race#locks#state-files#regression

Symptom

A record was marked sent by the auto-submit process, yet 90 minutes later its state card was back to draft without sentAt; a threshold counter saw 58 instead of 59. The card's aliveCheckedAt kept growing, which never happens for sent records.

Cause

The listener's sweep() took cards from a snapshot, waited for the browser lock for one of them, then saved its whole copy. Meanwhile the auto-submit, holding the lock, wrote sent. The listener's pre-wait copy landed on top: a lost update between two processes. The card then lived as a draft until expiry, and the finalizer saw sent in the draft file and left the card alone.

Rule

State written by several processes must be re-read from disk after any await that waits (lock, navigation, model call). Write into the fresh copy and only if the precondition (status) still holds. Regression: a stub wait function that writes 'as another process' during the wait.
