A health indicator bound to the old supervisor's PID file lies under systemd

2026-08-22 · Linux services#pid-file#systemd#supervisor

Symptom

The first /status after the migration answered 'monitor: STOPPED' although the monitor was running and the same line said 'last poll: 11 min ago'.

Cause

Liveness was derived from state/monitor.pid, written by the supervisor loop of the old run.sh. Under systemd there is no PID file, so the check silently fell into STOPPED. The same root could give the opposite error: 'running' from a stale PID file.

Rule

Bind health indicators to a fact, not to an artifact of one supervisor: a live process or the freshness of the last work result. When the launch method changes (setsid to systemd, systemd to a container), run every control command first and compare its answer with reality; they break silently because nothing formally fails.
