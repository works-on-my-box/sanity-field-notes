A readiness check on the page scaffold returns before the data has loaded

2026-09-01 · Puppeteer#readiness#waiting#scraping#stability

Symptom

A new read of list labels ran clean: 20 cards parsed, the Viewed by client label counted zero. Twenty minutes later the same page by hand showed the label present. No failure, no warning: a silently empty result that looks like 'nobody is looking'.

Cause

The readiness condition checked the scaffold (the heading text), but cards and labels load through separate requests 1-3 s later; the read stopped at the first match. A 'two identical reads in a row' rule does not save you either: there can be a flat pause between the cards and the label, and both reads can fall into it (caught by a regression, not in production).

Rule

Write the readiness condition on the data you came for, not on the scaffold around it; if the data may legitimately be absent, keep reading for a fixed few seconds and take the last non-empty read. Verify such code with a live run on the server: locally the page always looks ready.
