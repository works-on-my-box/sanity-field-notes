An awk date filter `$0 >= "2026-..."` passes every line that starts with `[`

2026-08-29 · Shell#logs#ascii#false-alarm

Symptom

awk '$0 >= "2026-08-28T08:00"' listener.log | grep -c "poll FAIL" reported 443 failures 'in a day' (really 10 and 7), and a 'funnel since the fix' turned out to be the whole history; half an hour went into a non-existent outage.

Cause

Log lines start with [, and [ (0x5B) is greater than any digit in ASCII, so $0 >= "2026-..." is true for every line; the output looked plausible (large but not absurd numbers).

Rule

Compare the date with the same prefix as the line (substr($0,1,len) >= "[2026-08-28T08:00"), and before raising any alarm check on the first printed line that its timestamp is at or after the boundary; if 'count for the period' equals 'count for all time', the filter is not working.
