Field notes — symptom → cause → rule, from an unattended browser-automation stack

Button captions are a markup version; blur validation can race the form model

2026-09-03 · Web forms#forms#validation#button-label#evidence#retries

Symptom

For an hour the auto-submit read a form as '4 required fields empty, no Send button', reloaded and refilled it 13 times, and closed the draft as expired. The screenshot at closing showed filled answers and a live green submit button with a new caption.

Cause

The site shipped a new form: the button became Submit proposal without the number the code searched for. Also, answers filled programmatically (native setter + input/change + blur) showed Value is required and can't be empty on non-empty fields because validation on blur ran ahead of the form model; a second pass with the same values cleared the errors (4 to 0). Each reload did exactly one pass and reproduced the same errors.

Rule

(1) Anything read by exact site text (caption, a number on it, an error phrase) is a markup version that changes without notice: match against a list of known captions and save evidence (screenshot plus the list of buttons and fields). (2) After programmatic fill, check validation errors next to each field, not just value; an error on a non-empty value means a second pass, not 'empty field'. (3) The same transient block after two or more identical refills is a code/site mismatch, not a page hiccup; tell the human what was searched and what is on screen.
