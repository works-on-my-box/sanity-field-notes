Field notes — symptom → cause → rule, from an unattended browser-automation stack

Measure download speed per CDN and machine before saying 'cannot download'

2026-09-29 · Shell#curl#bandwidth#huggingface

Symptom

From the laptop files.pythonhosted.org gave 24 KB/s (mirrors returned 403/404), download.pytorch.org 40 MB/s, Hugging Face 32 MB/s; from the VPS PyPI gave 20 MB/s, scp VPS to laptop about 3.5 MB/s, apt 0.6 MB/s.

Cause

Different CDNs are throttled differently from this network; the earlier one-off measurement (HF about 3 KB/s) was not representative.

Rule

Before concluding 'not downloadable', run curl -w speed_download per CDN from both machines; pull PyPI wheels on the VPS (python3 -m pip download --only-binary=:all: --platform manylinux2014_x86_64 --python-version 3.12 ...) and scp them over; take torch from download.pytorch.org/whl/cpu; for llama.cpp git clone from GitHub is fast while release archives are slow.

Supersedes Hugging Face measured at ~3 KB/s from both machines (later a one-off).
