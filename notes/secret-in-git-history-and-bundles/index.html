A secret removed from a file still lives in git history and in daily bundles

2026-08-26 · Git#secrets

Symptom

A secret answer was removed from a tracked file by an audit, but git grep over rev-list --all still found it in 171 versions of the file; the same commits sat in daily *.bundle backups posted to a chat.

Cause

Deleting a line is a new commit on top of the old ones; history, the remote and the bundles keep every previous version. 'Removed from the file' is not 'removed from the project's memory'.

Rule

A secret that reached the repo is purged by rewriting history: git filter-repo --replace-text (locally, pip install --user --break-system-packages git-filter-repo), git push --force, and on the server git fetch && git reset --hard origin/master && git reflog expire --expire=now --all && git gc --prune=now with the sync timer stopped; old bundles are deleted by a human. Commit hashes after the first affected one change, so older hash references become historical. Cheapest of all: never write the secret; if you did, purge it in the same session while it is one commit deep.
