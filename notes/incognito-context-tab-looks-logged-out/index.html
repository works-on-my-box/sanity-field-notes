Field notes — symptom → cause → rule, from an unattended browser-automation stack

An incognito-context tab always shows 'Log in'; check login on the default one

2026-09-29 · Puppeteer#tabs

Symptom

An alert said 'Chrome is not logged in'; the agent opened the monitor's search tab, saw Log in / Sign up and no avatar, and escalated to the user. The user opened the site in a new tab of the same Chrome: logged in.

Cause

The monitor's search tab lives in an incognito context (logged-out polling by design), so its header always says Log in. The alert came from one failed page read in the logged-in context, possibly disturbed by unrelated probes in the same Chrome at that time.

Rule

Check login state only on a page of the default context (browser.defaultBrowserContext().newPage() then open an account page and look for the avatar), never via the monitor's tab. Run one-off probes of other sites in a second Chrome and close your tabs afterwards (window.open of a foreign site spawns tabs unnoticed); do not call bringToFront in the working Chrome. Do not forward a single-read alert to a human without a second confirmation.
