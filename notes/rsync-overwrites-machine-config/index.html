Field notes — symptom → cause → rule, from an unattended browser-automation stack

rsync of code from the laptop overwrites the server's machine-specific config

2026-08-22 · Shell#config#deployment#selftest

Symptom

After the server's config.json was set to 127.0.0.1:9222, the next code sync put the laptop's browser address back: the selftest silently skipped the modal check, and the pipeline on the server would have gone blind on the first poll.

Cause

config.json sits next to the code and contains the browser address, a machine-specific setting in a file synced as code. .env and state/ were excluded from the sync; it was not.

Rule

While both machines are alive, sync code only with --exclude config.json --exclude state/ --exclude .env; after retiring the laptop, set the repository's config.json to the server values so the exclusion becomes unnecessary. The reverse side: after the migration the server writes the artifacts (ledgers), so before pushing code pull those directories first. Check after every sync with the selftest: 'Chrome unreachable over CDP' means exactly a drifted address.
