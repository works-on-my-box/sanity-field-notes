Two typing scripts in one browser: CDP keystrokes go to the active tab only

2026-09-24 · Puppeteer#cdp#keyboard#activeElement#forms

Symptom

A form filled from the laptop's Chrome ended with the name field empty and mail.com in the email field while other fields were fine; a second script was exploring another form in the same browser with its own bringToFront(). A solo retry still lost the first field: typing started before the page gave focus. The submit was stopped both times by a value self-check before the click.

Cause

CDP keyboard input goes to the active tab and active element; the second script switched tabs, and after page load the first click on the field did not focus it (a late page script).

Rule

One typing script per browser at a time (never run exploration and filling in parallel, even in different tabs). Before typing, assert document.activeElement === el, otherwise click/focus again and retry; after typing, read the value back and compare; click submit only when every field matches.
