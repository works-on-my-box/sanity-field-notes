Treating partial success as success silences the external watchdog

2026-08-25 · Linux services#monitoring#heartbeat#alerts

Symptom

Two polls in a row read only one query out of ten (nine hung for 60 s each), and the monitor reported a normal poll done, pinged the external watchdog and said nothing in the chat. The 'three polls without results' signal did not fire: it counts polls with zero, and here there was one success.

Cause

okSearches was used as a boolean 'something was read'. The external check would show 'monitor alive' while it was 90% blind: the pipeline wrote itself an alibi.

Rule

Health is a ratio, not a fact: a pass counts as healthy only if at least half of the queries were read. Ping the external watchdog only on a healthy pass; log an incomplete one separately and report a streak with numbers. More generally: for any success/failure aggregate, ask what it looks like at 10% success.
