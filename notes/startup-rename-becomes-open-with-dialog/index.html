Renaming inside the Windows Startup folder does not disable autostart

2026-08-27 · Windows & WSL#windows-startup#autostart#scheduled-tasks#migration

Symptom

At every Windows login a dialog Select an app to open this .disabled-2026-08-22 file appeared with a list of applications. The local pipeline had been considered disarmed since the migration, and no monitor processes existed on the machine.

Cause

Autostart was disabled by renaming the .vbs to .vbs.disabled-<date> while leaving it in the Startup folder. At login Windows tries to open everything in that folder regardless of extension; for an unknown extension it shows an app picker instead of running. The script indeed did not run, but the tail stayed visible to the human every day.

Rule

Disable autostart by moving the file out of the Startup folder (into the project's archive), not by renaming in place. Apply the same logic to any 'disabled by suffix' in directories the OS scans wholesale: /etc/cron.d, systemd/*/, conf.d. Verify by enumerating all logon sources (both Startup folders, Run/RunOnce in HKCU and HKLM, StartupApproved, Policies\Explorer\Run, scheduled tasks with an AtLogon trigger), not only the place you edited.

Supersedes A migration is not done while the old machine can resurrect daemons at login.
