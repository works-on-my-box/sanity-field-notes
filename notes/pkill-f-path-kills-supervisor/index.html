pkill -f on a path pattern kills the supervisor loop and the calling shell

2026-08-22 · Shell#pkill#supervisor#daemons#restart#pid

Symptom

pkill -f "node .*tg-listener.js" meant to restart a daemon also killed its supervisor loop (same path in its command line) and the calling command (exit 144). The listener stayed down unattended until noticed.

Cause

-f compares the pattern with the full command line of any process, including bash -c "while true; do node ..." and the current shell.

Rule

Restart daemons under a supervisor loop with their own tools (stop.sh, run.sh <name>, idempotent), not pkill. For a targeted kill use only the PID of the process itself (ps aux), never a path pattern. After any restart check ps and the log tail: a live supervisor without a node process looks almost like a working pipeline.
