Field notes — symptom → cause → rule, from an unattended browser-automation stack

A test that greps the source for a call name pins the form, not the behaviour

2026-09-06 · Node.js#testing#regression#mocks

Symptom

After injecting I/O points into handle() for a behavioural run, a check failed because it searched the source for the string verifyReply(cfg, ctx, out.reply; the path worked, as a new behavioural run showed. The same check had never caught a real defect on that path.

Cause

A source-text check verifies the call's name, not its result: a refactor breaks it for no benefit, and a real bug on the same path passes it.

Rule

Regressions for pipeline scenarios are runs of the path with injected I/O points (thread, send, model, re-check; notifications and ledger through options), without a browser or a model; source-text checks only for what cannot be tested otherwise (a notification text, the presence of a command).
