Clicks outside the viewport fail silently; tabs in a shared Chrome can vanish

2026-09-02 · Puppeteer#click#idempotency

Symptom

page.mouse.click at the centre of a button's boundingBox 'worked' but no modal opened. Later the run died twice mid-way (Target closed, Navigation timeout); a page.on('close') watchdog confirmed the tab was closed from outside. Save had already gone through, so the edit was in place although the script ended with an error.

Cause

(1) For an element below the fold boundingBox returns coordinates outside the viewport; a real mouse click lands outside the window without any error. (2) A one-off script's tab lives in the shared Chrome of the daemons: tab cleaners, memory discards and restarts promise it nothing, and 'run died' is not 'edit failed' (nor the reverse).

Rule

Before a click, scrollIntoView and assert the point is inside the viewport (fail instead of clicking). Attach page.on('close') to the tab. Collect the proof of the result in a separate short read-only pass after the run, not as the tail of a long script. Before repeating a 'failed' edit, check the state of the world; every re-runnable edit script needs an idempotency guard.
