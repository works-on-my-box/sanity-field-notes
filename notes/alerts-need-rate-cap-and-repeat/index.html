Alert extremes: firing every 30 s under Restart=always, or exactly once

2026-08-24 · Linux services#alerts#systemd#restart#rate-limit

Symptom

Found by reading the code before hand-off. With Restart=always, a missing password in .env made the daemon post 'did not start' and exit: it would post that every 30 seconds forever. The opposite extreme in the same file: with IMAP dead the alert went out on the third failure and never again, and the daily canary went quiet together with IMAP, so a broken daemon would look like 'all quiet'.

Cause

Alerts were written case by case and none answered 'what will the human see if the cause persists for a week'. A hammering alert gets muted together with the channel; a single one gets lost in the feed.

Rule

Give every alert two numbers: a frequency cap (a marker file with a timestamp, at most once per N hours) and a repeat period while the cause persists. Separately check that the self-check does not fall silent with the alert: if the canary lives inside the broken loop, silence proves nothing.
