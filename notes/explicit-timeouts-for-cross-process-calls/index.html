A successful navigation is not a live page: explicit timeout on every evaluate

2026-08-25 · Puppeteer#timeouts#monitoring

Symptom

The daemon was active, six minutes without a log line, then a vague Runtime.callFunctionOn timed out. The human never learned that an interstitial page was sitting on screen, which is exactly what the signal was written for.

Cause

On the interstitial page the renderer does not respond to evaluate at all. The code waited for puppeteer's default protocolTimeout of 180 s, and the first call swallowed the timeout as 'empty text' and moved on. The 'is this an interstitial?' check only lived in the navigation-failure branch, and the navigation had succeeded.

Rule

Every call into another process gets its own explicit deadline, shorter than any default. Treat silence from the other process as the worst known cause and alert the human, instead of recording an empty result and moving on.
