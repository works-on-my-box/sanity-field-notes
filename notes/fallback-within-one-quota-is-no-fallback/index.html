Fallback between models sharing one subscription quota protects nothing

2026-09-08 · Coding agents#claude-code#fallback#rate-limit

Symptom

The config listed fallback chains like [opus, haiku] and [sonnet, haiku] as availability insurance.

Cause

Only one model line had a separate limit counter; the other three shared the subscription quota. Confirmed on the server: one line returned 429 while the others still answered. A backup from the shared quota fails at exactly the same moment as the primary.

Rule

Put fallbacks only between models with independent quotas. Within one quota a second model makes sense only as a different model for independent review, not as availability insurance; where nothing can insure, an empty chain and fail-closed (alert the human) is more honest than answering with an unmeasured model.

Supersedes Headless `claude -p`: no --bare, cwd outside the repo, per-model fallback chain.
