Field notes — symptom → cause → rule, from an unattended browser-automation stack

A top-N error summary must apply N to normalized kinds, not raw lines

2026-08-23 · Linux services#logging#summary#alerts

Symptom

The morning summary said 'errors in logs: 90' and listed five, all the same network stutter of the chat poller. Real events of the same night (search FAIL: net::ERR_CONNECTION_CLOSED, a failed heartbeat ping) did not make it into the message.

Cause

The summary took errs.slice(0, 5), the first five lines in file order. One class repeated dozens of times fills the whole display, and the noisier the channel, the more reliably the rare event hides.

Rule

Apply N to kinds, not lines: normalize the message (numbers to N), group, show each kind with its multiplicity (11x poll FAIL fetch failed). The noisy class takes one line and the rare event is always visible. Keep the total line count next to it: it reports the health of the link.
