A site restores its autosaved draft asynchronously over freshly typed text

2026-09-20 · Web forms#editor#typing#verification

Symptom

On a reply form the typed text was replaced a few seconds later by the previous version; three runs in a row would have sent the old text, and a title field was sent with the content doubled (ParserParser ...).

Cause

The site saves a draft of the reply itself and restores it after page load, asynchronously and after the script had already cleared the editor and started typing. The title script also typed over a non-empty field.

Rule

After navigation wait until the editor's content length stops changing (three identical readings), then clear and type. Before typing into any field, assert it is empty; after typing, compare the result with the source file character by character. If the site does not allow editing after submit, verification must happen before the click.
