Field notes — symptom → cause → rule, from an unattended browser-automation stack

A copied interactive CLI login expires; daemons need `claude setup-token`

2026-09-16 · Coding agents#claude-code#credentials#daemons

Symptom

For three hours every model call from the daemon answered Failed to authenticate: OAuth session expired and could not be refreshed; each job retried four times and sent a 'submit manually' message to the user.

Cause

The CLI login on the server had been copied from the laptop. An interactive subscription login has a hard expiry stored in ~/.claude/.credentials.json as refreshTokenExpiresAt; once past it, the first expired access token could not be refreshed and the CLI wiped both tokens. The expiry had been sitting in the file for 25 days unread. The pipeline also had no class for 'shared outage', so each job cycled through models. A long-lived token would not have worked either: the wrapper scrubbed ^CLAUDE from the environment and would have dropped CLAUDE_CODE_OAUTH_TOKEN.

Rule

Give daemons a login issued for the machine: claude setup-token (one year, scope user:inference) in .env, not a copy of an interactive login (shorter life, broader rights). When moving or issuing a credential, write down the day it dies and check environment filters on the call path. Treat a dependency shared by all models (login, the whole API) as its own error class: one message to the human with one action, hold the work and resume automatically. Capture error texts for regressions from the live CLI, not from imagination.
