'Saved in the repo' needs git ls-files: .gitignore silently dropped the file

2026-09-07 · Git#commit#verification

Symptom

A commit message and the handoff said a measurement script was saved at tools/.../probe-style.js; the file was not in the repo (git ls-files empty, absent on the server) because a local .gitignore had probe*.js from the days of one-off probe scripts.

Cause

The claim was written from the fact of writing to disk, not from the fact of landing in a commit; git add -A quietly skips ignored files.

Rule

Confirm any 'saved in the repo' with git ls-files <path>; a file whose name matches an ignore mask needs an explicit !name in .gitignore.
