Markup sampled from page one of a list does not describe page two

2026-09-01 · Puppeteer#scraping#fixtures#regex#dedup

Symptom

A list parser returned 22 cards, five of them titled last week, last week, last week, last week and Boosted instead of titles. The regression was green and the production run showed no errors because it never reached page two.

Cause

Fixtures were captured from the first page, where items are fresh: age reads 4 days ago and the only badge is one known label. On page two older items have age spelled as words (last week, last month) and a different badge. Neither form was in the age or label patterns, so that line became the title. The cost is not just noise: the event key built from the title would diverge from the same event's key elsewhere, and one event would be reported twice.

Rule

When sampling list markup, sample every page, not just the first: time changes not only the data but the words the site uses for it. Enumerate the age and badge forms explicitly and put a fixture from the farthest page into the regression.
