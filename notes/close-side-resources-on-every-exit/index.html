Field notes — symptom → cause → rule, from an unattended browser-automation stack

Whoever opens a side resource closes it, on every exit path including returns

2026-08-23 · Puppeteer#tabs#cleanup#cdp#json-list

Symptom

After 13 hours on the server, the logged-in Chrome held two open form tabs, exactly as many as items the model had skipped. No errors in the logs and no tabs closed lines at all.

Cause

The drafter opens the form tab for a read before the model's decision, and only the listener closed it, on the draft's terminal status. A skipped item has no draft and never reaches the listener, so the decision !== 'draft' branch returned past any cleanup. Classic asymmetry: cleanup on the success path, three early exits without it.

Rule

If a function opens a side resource (tab, context, file, lock) for an intermediate read, the release is written next to the open and covers all exits, including early returns on refusal. Do not rely on the next component in the chain: it runs only on some paths. Cheap check: curl -s http://<cdp>/json/list and count pages; more than expected means a path without cleanup.
