Config reached the server but nothing changed: the daemon reads it once

2026-09-01 · Linux services#config#daemons#restart#deployment#locks

Symptom

git push, sync on the server, config.json in the working directory new, HEAD matching, units active. The next poll still read all nine queries as if nothing had changed.

Cause

const cfg = JSON.parse(fs.readFileSync(...)) runs once at module load; the monitor is a --loop process that lives for days. Only .env is re-read (reloadEnv() on every poll), which created the false impression that config is picked up by itself.

Rule

Consider a config rollout done only after restarting the consumer and seeing live proof in the log (here: a poll listing exactly the new queries). Restart a daemon that holds a lock on a shared resource in the window between cycles (sleep NNNs in the log, lock free), and verify the lock expires on its own so a mid-cycle crash does not block the pipeline. Before a rollout answer 'what is re-read by itself and what only at start' instead of assuming.
