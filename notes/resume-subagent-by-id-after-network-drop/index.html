A subagent that died on a network drop should be resumed by ID, not restarted

2026-09-19 · Coding agents#subagents#claude-code

Symptom

The user's internet dropped. A research subagent failed with EAI_AGAIN mid-work, while the pages it had already downloaded were lying in the scratchpad.

Cause

The subagent calls the API from the laptop. The server and its daemons do not depend on the laptop's network, so nothing broke there.

Rule

Continue a subagent that died on the network via SendMessage to its ID: its context is kept and the downloaded files are re-read from disk; a fresh launch repeats all the work. After a drop check three things: the server (units, locks, last poll), git (local equals origin), and unfinished background tasks.
