A page returned on timeout with partial content looks like an empty page

2026-08-25 · Puppeteer#timeouts#scraping#llm-input#logging

Symptom

Five of 72 alerts ended in a model refusal with 'the description breaks off mid-sentence' or 'generic phrases without a single fact'. All five had an empty full description and an unread secondary block: the page simply had not finished loading.

Cause

The fetch waited up to 30 s for text and on timeout returned whatever had rendered, without an error. The parser then honestly returned empty fields, and the drafter fell back to the card summary from the listing, which is truncated to 300 characters on write. The model got a fragment without knowing it was one.

Rule

Distinguish 'read and empty' from 'not read': a read of an external page needs a completeness flag, and no decision is made on incomplete data (either re-read or tell the model explicitly that the description is incomplete). Truncation when writing a log (300 chars) is not a storage detail but a ceiling on decision quality when someone decides from that log.
