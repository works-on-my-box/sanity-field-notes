Tab cleanup keyed on the pre-action ID finds nothing once the URL changes

2026-08-22 · Puppeteer#tabs#cleanup#logging

Symptom

After every send the log said tabs closed 0, and confirmation tabs piled up in the browser (three in two days) although cleanup ran and raised no errors.

Cause

closeJobTabs looked for tabs by the item ID in the URL, but a successful send navigates to /proposals/<proposalId>?success, a different identifier from a different namespace. Zero closed tabs read as 'nothing to close' rather than 'not found'.

Rule

If an action changes the tab's URL, cleanup cannot rely on the 'before' identifier alone: remember the 'after' identifier (it is in the outcome confirmation) or close by the result-page signature. A done 0 counter in a log is not proof of success; for cleanup log what was searched for and what was found.
