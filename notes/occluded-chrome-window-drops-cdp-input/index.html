A fully covered Chrome window silently drops CDP input (visibilityState hidden)

2026-08-27 · Chrome & DevTools Protocol#cdp#windows

Symptom

Two runs hung on human-like mouse clicks; a third typed a title and tags into nothing (field values unchanged, no errors). document.visibilityState === 'hidden' with windowState: normal: another application's window was covering Chrome.

Cause

Windows occlusion tracking: a fully covered Chrome moves the renderer to the background and does not deliver synthetic input (the mouse waits for an ack forever, keys are lost). Earlier successful edits ran while the window was visible.

Rule

Before any CDP input check document.visibilityState === 'visible'; launch channel Chromes with --disable-backgrounding-occluded-windows --disable-renderer-backgrounding --disable-background-timer-throttling --disable-features=CalculateNativeWinOcclusion; an already running Chrome is cured only by a restart. Put every script step under a timeout (Promise.race) with a log file so a hang is visible instead of a bare Terminated.
