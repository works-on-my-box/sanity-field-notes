tls.connect(port, host, cb) sends no SNI; Gmail's default cert looks like MITM

2026-08-23 · Node.js#imap#gmail

Symptom

An IMAP login check from the server failed with ERR self-signed certificate connecting to imap.gmail.com:993. On a rented datacenter machine that reads as TLS interception, right when an app password was about to be sent there.

Cause

The positional form tls.connect(993, 'imap.gmail.com', cb) does not pass servername, so no SNI is sent. Without SNI Gmail serves a default certificate whose chain does not verify. No interception: openssl s_client -connect imap.gmail.com:993 -servername imap.gmail.com showed the real chain and Verify return code: 0 (ok).

Rule

Write TLS clients only in the object form: tls.connect({ host, port, servername }). Before declaring 'we are being intercepted', verify the chain with an independent tool: a certificate error far more often means a bug in your own code than an attack.
