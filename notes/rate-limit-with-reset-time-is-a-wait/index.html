Field notes — symptom → cause → rule, from an unattended browser-automation stack

An error that names its reset time is a wait state, not a terminal failure

2026-09-09 · Coding agents#rate-limit#claude-code#fallback

Symptom

Both models answered You've hit your session limit · resets 4:10pm; the pipeline handed the job to a human as failed and exited, 12 minutes before the reset, while the job's window still allowed 110 minutes.

Cause

The wrapper only knew 'limit means next model', and at the end of the chain any error was terminal. The CLI states the reset time in the error, but the code did not read it; with a shared subscription limit there is no 'next model', and the only working move is to wait until the named moment.

Rule

An error that names the moment the block lifts is neither a failure nor a decision: queue the job until that moment if it is before the deadline, and close with a fact if it is after. 'Submit manually' in unattended automation is a loss, not a safety net. Implemented as a limitReset parser plus pending/retryAfter state.
