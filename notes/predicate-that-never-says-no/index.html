A check that cannot answer 'no' is a constant: count a predicate's answers

2026-08-25 · Node.js#testing#fetch#fixtures#logs

Symptom

A jobAlive function answered 'alive' for five days on every question, closed jobs included. No error in the logs: the 'closed by client' rule simply never fired.

Cause

Liveness was read as fetch('https://.../jobs/~id/') from an open tab, judged by the words no longer available in the response. The site answered a programmatic request with a 403 interstitial that never contains those words, so a negative answer was physically unreachable: the function could only return true or throw.

Rule

Ask of any predicate not 'does it work' but 'what does its negative answer look like and have we ever seen one'. If the logs contain no false, the check is considered broken until shown otherwise on a deliberately broken case. In log reviews count the distribution of each predicate's answers, and keep a fixture for the 'no' branch (the interstitial text and a closed-item text).
