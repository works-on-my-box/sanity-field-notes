A command-line flag does not survive into deferred work sent by another process

2026-08-24 · Node.js#state-files#daemons

Symptom

A test marker was added as the first line of --test-alert output. But the test email also creates a reminder, and reminders 45 and 180 minutes later are sent by the inbox daemon, a separate process started without flags: only the first message would carry the marker, the next two would look real.

Cause

The mode lived in process.argv, i.e. in the memory of one run, while the event outlived that run: it was written to state/pending/<key>.json and became another process's work. Whatever outlives its process loses the mode at the boundary.

Rule

If an action leaves a record from which someone else will later send a message, the mode marker goes into that record (test: true), not only into the current output. Check by asking: who sends the next message about this event, and do they know it is a test?
