Sparse new Array(n) fixtures vanish under filter; grep every .length consumer

2026-09-01 · Node.js#fixtures#selftest

Symptom

Four of nine search queries got "off": true and the poll went down to five. The regression failed on a neighbouring check: 'one result out of ten means a failed poll' returned true, i.e. a blind poll counted as successful.

Cause

Two traps of one shape: 'the list length stopped meaning what it meant'. First, poll health was computed as okSearches * 2 >= cfg.queries.length, and after turning off four queries the denominator stayed nine, so every poll would be 'incomplete' forever and the external watchdog would never be pinged. Second, the test fixture new Array(10) is a sparse array, and filter skips holes, so the count of live queries collapsed to zero and any number of results passed.

Rule

When adding an 'off' flag to a collection, grep for .length of that collection and decide for each place whether it means the whole list or the live part; in fixtures use Array.from({length: n}, () => ({})), not new Array(n), otherwise any filter/map in the code under test silently empties the fixture. A rule extracted from source by a test (new Function over a match) must stay expressible in the same arguments.
