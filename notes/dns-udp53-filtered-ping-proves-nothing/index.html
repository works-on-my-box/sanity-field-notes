Field notes — symptom → cause → rule, from an unattended browser-automation stack

Scattered network errors were one filtered UDP/53 uplink; ping proves nothing

2026-08-23 · Linux services#vps

Symptom

In one day: git sync failed with Temporary failure in name resolution, the external watchdog reported the monitor DOWN, two browser searches failed with ERR_NAME_NOT_RESOLVED. ping to 8.8.8.8, 1.1.1.1, the hoster's resolver and the gateway showed 0% loss and flat RTT.

Cause

The first DNS uplink in netplan was 8.8.8.8, and outbound UDP/53 is filtered from this network: dig @8.8.8.8 answered 3 of 20, @1.1.1.1 5 of 20, the datacenter's local resolver 19 of 20, while dig +tcp to both public ones was 5/5. systemd-resolved preferred the first server and waited for a timeout on each miss. ICMP is answered by the router/resolver itself and says nothing about UDP packets to port 53.

Rule

When 'random' network errors appear across several daemons on one machine, look for the shared lower layer (resolver, MTU, uplink) rather than fixing each daemon. Measure DNS by resolving through each uplink separately (dig @server, a series of 20), not by ping, and do it on day one of a rented machine: the hoster's default may be nearly non-functional. Public resolvers are not a universal answer; the datacenter's or provider's resolver is often the only working one.
