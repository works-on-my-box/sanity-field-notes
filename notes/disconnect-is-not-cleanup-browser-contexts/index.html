Disconnecting from Chrome does not remove the browser contexts a process created

2026-08-25 · Puppeteer#memory#cleanup#restart#cdp

Symptom

Chrome on the server accumulated 12 pages, 10 iframes and 30 workers, using 2.7 GB of 3.9 GB. Nine of the pages were copies of search results and item pages nobody touched.

Cause

On every process start the monitor creates its own incognito context (browser.createBrowserContext()) and on exit only disconnects. The context with all its tabs stays in Chrome forever: every daemon restart adds one live page that keeps eating memory. Cleanup existed only for item tabs in the default context.

Rule

Disconnect is not cleanup. Whatever a process created inside a long-lived foreign application (context, tab, temporary profile) it must remove either on exit or on the next start; the latter is more reliable because it survives a crash. Verify live, not by reading code: count objects in the application before and after a restart. Result here: 12 pages to 2, 2707 MB to 1128 MB.
