Closing the last tab over CDP exits Chrome; hung embeds block load events

2026-09-03 · Chrome & DevTools Protocol#cdp

Symptom

A script using goto with waitUntil: domcontentloaded (60 s) failed twice with Navigation timeout on the 6th-7th navigation of a series although the page was visibly rendered; readyState was loading/interactive and an embedded JSON blob was empty or truncated. Trying to revive the tab via /json/close/<id> closed the last window: Chrome exited and the CDP port went dead.

Cause

The page keeps long-running loads (third-party iframes, trackers, a support widget): the load event does not fire while they hang, and after a series of searches they hang longer. A Chrome window with a single tab dies with it; CDP close does not distinguish a tab from the last tab.

Rule

For a series of pages: PUT /json/new?<url> (new tab, no waiting), pause 10-15 s, close the previous tab, read the current one; parse embedded JSON only when readyState === 'complete', otherwise wait and re-read. Never close a tab that is the last one in the profile; open the next one first. After any closes check the port with curl -w '%{http_code}'.
